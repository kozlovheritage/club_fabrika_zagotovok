# Авторизация клуба «Фабрика заготовок»

Ветка `auth/prodamus` содержит серверную авторизацию. Только для **расширенного тарифа**, после подписанного успешного уведомления Prodamus и проверки заказанного товара и фактически оплаченной суммы, сервер открывает бессрочный доступ и отправляет покупателю письмо с данными для входа. Для базового тарифа клубный вход не создаётся: письмо с доступом к материалам должен отправлять Prodamus. Повтор уведомления по тому же номеру заказа не выдаёт второе письмо.

## Подготовка ONREZA

Разверните эту ветку отдельно для проверки как **Compute**, а не Static, с Node.js >=20 и командой `npm start`. Не переключайте опубликованный `main`, пока не проверите оплату и вход. В тестовом окружении `PUBLIC_URL` должен указывать на тестовый HTTPS-адрес, иначе письмо направит клиента на текущий основной сайт. Нужна PostgreSQL и переменные из `.env.example`: `DATABASE_URL`, `PUBLIC_URL` (HTTPS-адрес сайта), `PRODAMUS_SECRET_KEY`, `AUTH_CREDENTIAL_KEY` (случайная строка не короче 32 символов), `COOKIE_SECURE=true`. Не добавляйте значения ключей в GitHub. Не меняйте `AUTH_CREDENTIAL_KEY`, пока остались неотправленные письма.

Для отправки писем выберите **одного** провайдера. При `AUTH_EMAIL_PROVIDER=resend` нужны `RESEND_API_KEY` и `AUTH_FROM_EMAIL` в формате Resend. При `AUTH_EMAIL_PROVIDER=notisend` нужны `NOTISEND_API_KEY` и `AUTH_FROM_EMAIL` как обычный email-адрес без имени и угловых скобок; `AUTH_FROM_NAME` необязателен. NotiSend принимает одиночные письма по API в очередь; ответ «queued» ещё не гарантирует доставку. Перед массовой отправкой проверьте доступный лимит тарифа и доставляемость писем.

## Настройка Продамус

Для тестирования временно укажите URL тестового Compute-развёртывания; после публикации основного сайта установите URL для уведомлений: `https://club-fabrika-zagotovok-kozlovheritage.onreza.app/api/webhooks/prodamus`. Если используется `sys`, задайте точно такое же значение в `PRODAMUS_SYS`. Установите `BASIC_PRICE_RUB`, `PREMIUM_PRICE_RUB` в целых рублях по актуальным ценам и `SALES_ORIGINS` — разрешённые HTTPS-адреса сайта продаж через запятую. Без цен сервер не создаёт заказы. Виджет на сайте продаж открывает ту же форму `vera-mlgn.payform.ru`; сервер генерирует подписанный номер заказа, а по webhook сверяет его с тарифом, названием товара, ценой и итоговой суммой (`sum`). В уведомлении Prodamus собственный `order_id` отличается от номера нашего заказа `order_num`. Другие платежи (например, с общей формы или через чат-бота) не создают вход в платформу автоматически.

Перед включением кнопок обязательно подтвердите, что Prodamus отправляет **отдельное письмо базового тарифа** с правильными материалами только после его успешной оплаты. Пока это не проверено, сервер отвечает 503 на попытку начать базовую оплату; разрешение включается переменной `BASIC_CHECKOUT_ENABLED=true` только после готовности письма. Письмо с приватной ссылкой нельзя передавать через публичный JavaScript или открытый API: покупатель увидит его до оплаты. Для расширенного тарифа уникальные данные входа отправляются сервером клуба через настроенный почтовый провайдер. Цена, действовавшая при открытии виджета, включена в подписанный номер заказа; более позднее изменение цены не лишит уже оплатившего покупателя доступа.

## Проверка перед публикацией

1. В Preview проверьте создание заказа для обеих кнопок, реальные поля `order_num`, `products`, `sum` и `Sign` в уведомлении после покупки. Тестовое уведомление без подписанного номера заказа не выдаёт вход.
2. Для базового тарифа проверьте письмо Prodamus и отсутствие входа в платформу; для расширенного — письмо клуба и вход. Повтор webhook (в том числе с новым `attempt`) не должен отправлять повторное письмо.
3. Проверьте неверный `Sign` (отказ), сбой почты (ответ 500 и повтор отправки), вход/выход, а также что `/club` не показывает материалы без авторизации.
4. Только после этого переносите конфигурацию на основной домен и объединяйте ветку с `main`.
