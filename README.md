# Авторизация клуба «Фабрика заготовок»

Ветка `auth/prodamus` содержит серверную авторизацию. Для новых заказов с сайта продаж Prodamus отправляет письмо обоим тарифам: базовому — приглашение в закрытый Telegram-клуб, расширенному — адрес платформы, email и персональный пароль. Только для **расширенного тарифа**, после подписанного успешного уведомления Prodamus и проверки товара, email и фактически оплаченной суммы, сервер создаёт бессрочный вход. Базовому покупателю вход в платформу не создаётся. Пароль расширенного заказа не действует до подтверждения оплаты.

## Подготовка ONREZA

Разверните эту ветку отдельно для проверки как **Compute**, а не Static, с Node.js >=20 и командой `npm start`. Не переключайте опубликованный `main`, пока не проверите оплату и вход. В тестовом окружении `PUBLIC_URL` должен указывать на тестовый HTTPS-адрес, иначе письмо направит клиента на текущий основной сайт. Нужна PostgreSQL и переменные из `.env.example`: `DATABASE_URL`, `PUBLIC_URL` (HTTPS-адрес сайта), `PRODAMUS_SECRET_KEY`, `AUTH_CREDENTIAL_KEY` (случайная строка не короче 32 символов), `COOKIE_SECURE=true`. Не добавляйте значения ключей в GitHub. Не меняйте `AUTH_CREDENTIAL_KEY`, пока остались неотправленные письма.

Для **новых** заказов с сайта сервис email не нужен: письмо с доступом отправляет Prodamus. Старые тестовые заказы с ранее выданным номером `fz2` по-прежнему используют отправку из клуба: при `AUTH_EMAIL_PROVIDER=notisend` нужны `NOTISEND_API_KEY` и `AUTH_FROM_EMAIL` в виде обычного email-адреса. Не отключайте этот механизм, пока остались старые неоплаченные заказы.

## Настройка Продамус

Для тестирования временно укажите URL тестового Compute-развёртывания; после публикации основного сайта установите URL для уведомлений: `https://club-fabrika-zagotovok-kozlovheritage.onreza.app/api/webhooks/prodamus`. Если используется `sys`, задайте точно такое же значение в `PRODAMUS_SYS`. Установите `BASIC_PRICE_RUB`, `PREMIUM_PRICE_RUB` в целых рублях по актуальным ценам и `SALES_ORIGINS` — разрешённые HTTPS-адреса сайта продаж через запятую. Без цен сервер не создаёт заказы. Виджет на сайте продаж открывает ту же форму `vera-mlgn.payform.ru`; сервер генерирует подписанный номер заказа, а по webhook сверяет его с тарифом, названием товара, ценой и итоговой суммой (`sum`). В уведомлении Prodamus собственный `order_id` отличается от номера нашего заказа `order_num`. Другие платежи (например, с общей формы или через чат-бота) не создают вход в платформу автоматически.

`BASIC_ACCESS_URL` — приглашение в закрытый Telegram-клуб; задаётся **секретом окружения**, не публикуется в GitHub и не передаётся виджету. Письмо базовому содержит индивидуальную ссылку на клубный сервер: после подтверждённой оплаты она одним переходом открывает приглашение в Telegram, до оплаты — ничего не выдаёт. Пока письмо после оплаты не проверено и приглашение не настроено, оставьте `BASIC_CHECKOUT_ENABLED=false`. Email покупателя должен быть обязательным в самой форме Prodamus. Для расширенного `paid_content` содержит персональный пароль: он передаётся браузеру до оплаты, но начинает действовать только после подтверждённого webhook. Уже существующий email с паролем не может заказать расширенный тариф повторно. Если ранее были открыты два разных заказа на один email и оба оплачены, каждый заказ создаёт отдельную внутреннюю запись со своим действующим паролем, а покупатель в обоих случаях вводит свой обычный email. Цена включена в подписанный номер заказа и не зависит от более позднего изменения прайса.

## Проверка перед публикацией

1. В Preview проверьте создание заказа для обеих кнопок, реальные поля `order_num`, `products`, `sum` и `Sign` в уведомлении после покупки. Тестовое уведомление без подписанного номера заказа не выдаёт вход.
2. Для базового тарифа проверьте письмо Prodamus с приглашением и отсутствие входа в платформу; для расширенного — письмо Prodamus с email и паролем и успешный вход. Повтор webhook (в том числе с новым `attempt`) не должен менять пароль.
3. Проверьте неверный `Sign` (отказ), другое имя товара/сумму/email в webhook, повторную покупку существующего email, вход/выход и что `/club` не показывает материалы без авторизации.
4. Только после этого переносите конфигурацию на основной домен и объединяйте ветку с `main`.
